# QuantTrader 프로젝트 역할 정리

## 목적

현재 구조에서 각 프로젝트가 무엇을 책임지고, 무엇을 책임지지 않는지를 명확히 정리한다.

핵심 원칙은 아래와 같다.

- 전략 규칙은 `QuantTrader.Strategies`가 가진다.
- 전략 검증은 `QuantTrader.Researcher`가 담당한다.
- 실주문 집행은 `QuantTrader.Trader`가 담당한다.
- 데이터 수집은 `QuantTrader.Collector`가 담당한다.
- 프로젝트 간 데이터 형식은 `QuantTrader.Contracts`가 담당한다.

## 전체 프로젝트 구성

```text
src/
  QuantTrader.Collector/
  QuantTrader.Contracts/
  QuantTrader.Researcher/
  QuantTrader.Strategies/
  QuantTrader.Trader/
  QuantTrader.WebUI/
```

## 전략의 핵심 구성 요소

전략은 최소한 아래 4가지를 가져야 한다.

1. 대상주 선정
2. 매수 시점
3. 손절 시점
4. 익절 시점

그 외 규칙은 전략별 특성에 따라 추가된다.

예:

- 시간 종료 청산
- 분할 진입
- 거래량 조건
- 리스크 제한
- 포지션 크기 산정

## QuantTrader.Strategies

### 역할

전략의 규칙만 정의한다.

### 포함 내용

- 전략별 대상주 선정 규칙
- 매수 규칙
- 손절 규칙
- 익절 규칙
- 전략 파라미터 타입
- 전략 상태 타입
- 전략 공통 인터페이스 및 추상화

### 포함하지 않는 것

- DB 조회
- 주문 API 호출
- 실시간 루프
- 백테스트 결과 저장

### 구조 방향

하나의 프로젝트 안에서 전략별 폴더로 나눈다.

예:

```text
QuantTrader.Strategies/
  Abstractions/
  Orb/
    Filters/
    Entry/
    Exit/
    Risk/
```

전략별로 프로젝트를 나누지는 않는다.

## QuantTrader.Researcher

### 역할

전략을 검증하고 백테스트한다.

### 포함 내용

- 과거 분봉/스냅샷 조회
- 전략 파라미터 조합 반복 실행
- `ResearcherEngine`을 통한 전략 실행
- 가상 주문 및 가상 체결
- 손익/승률/MDD 계산
- 결과 저장 및 조회
- 연구/백테스트 API 제공

### 포함하지 않는 것

- 실제 주문 API 호출
- 실제 체결 처리
- 포지션 실운영 관리

### 핵심 해석

`Researcher`는 전략 자체를 정의하지 않는다.
정의된 전략을 과거 데이터에 적용하고, 결과를 실험/검증하는 주체다.

## QuantTrader.Trader

### 역할

활성화된 전략을 실제 시장에 집행한다.

### 포함 내용

- ON 된 전략과 파라미터 로드
- 당일 분봉을 읽어 `TraderEngine` 실행
- 실제 주문 의도 생성 및 브로커 주문 호출
- 체결/미체결/취소 상태 관리
- 포지션 상태 관리
- 중복 주문 방지

### 포함하지 않는 것

- 대규모 파라미터 탐색
- 연구용 결과 비교
- 백테스트 요약 계산

### 핵심 해석

`Trader`는 전략을 선택하거나 검증하는 주체가 아니다.
이미 선택된 전략을 실제로 집행하는 주체다.

## QuantTrader.Contracts

### 역할

프로젝트 간 공통 데이터 형식을 정의한다.

### 포함 내용

- 요청 DTO
- 응답 DTO
- 주문 의도 모델
- 공통 enum
- 결과/요약 모델

### 포함하지 않는 것

- DB 접근
- 외부 API 호출
- 비즈니스 로직

### 핵심 해석

`Contracts`는 통신을 담당하지 않는다.
통신에 쓰는 데이터 형식만 표준화한다.

## QuantTrader.Collector

### 역할

시장 데이터를 수집해서 DB에 적재한다.

### 포함 내용

- 한국투자증권 API 호출
- 토큰 발급 및 재사용
- 종목 마스터 갱신
- 장중/장마감 분봉 적재
- PostgreSQL 저장

### 포함하지 않는 것

- 백테스트
- 전략 검증
- 주문 판단
- 주문 집행

### 핵심 해석

`Collector`는 데이터 공급자다.
분석과 주문은 하지 않는다.

## QuantTrader.WebUI

### 역할

사용자 화면을 제공한다.

### 포함 내용

- 파라미터 입력
- 결과 조회
- 연구용 화면
- 상태 확인

### 메모

현재는 우선순위가 낮다.
전략과 백엔드 구조가 충분히 정리된 뒤 다시 설계할 수 있다.

## 현재 책임 경계 요약

- `Strategies`
  - 전략 규칙
- `Researcher`
  - 전략 검증
- `Trader`
  - 전략 집행
- `Contracts`
  - 공통 형식
- `Collector`
  - 데이터 수집
- `WebUI`
  - 화면

## 현재 우선순위

1. `QuantTrader.Strategies`
2. `QuantTrader.Researcher`
3. `QuantTrader.Trader`

`QuantTrader.WebUI`는 후순위로 둔다.
